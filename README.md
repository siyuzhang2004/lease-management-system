# 租赁管理系统

面向承租人财务核算的本地网页项目，以“合同 → 计算参数 → 计算表”组织业务流程。

## 当前功能

- 按合同保存财务参数、计算结果及参数版本。
- 分阶段设置租金、阶段月数、付款频率和期初／期末付款。
- 修改参数后自动计算使用权资产和租赁负债余额。
- 按期间查看逐期明细和年度汇总，并从计算表回看合同参数。
- 高级参数录入、必要的计量校验及合同删除与恢复。
- 按公司、期间查看使用权资产附注，支持原币与人民币折算、金额追溯和版本保存。
- 支持日本租赁按整数截尾及末期尾差结清。

部分复杂条款尚需补充现金流配置，系统会提示复核，不会忽略相关条款继续生成新表。目前不提供文件导入导出、实际付款管理或会计凭证功能。

## 本地运行

需要 Python 3.10 或更高版本。前端使用原生 HTML、CSS 和 JavaScript，不需要构建工具。

在项目目录中运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe prototype/server.py
```

浏览器打开 <http://127.0.0.1:8765/>。服务仅监听本机地址。

首次启动直接进入合同台账，自动载入 **8 家公司、9 份合同**：西安、深圳、耐数电子、耐数信息、日本、美国、韩国各一份，欧洲两份。合同参数、汇率、欧洲旧租赁历史数据和附注期初承接数据均随仓库提供，计算表在本机根据参数生成。无需另行提供原始合同或工作簿，即可查看公司单体、普源集团及耐数集团的两种附注。

西安默认参数位于 `prototype/default-contract.json`；其余初始化数据位于 `prototype/seed-data/`。现有 2026 年 6 月、9 月集团附注可直接查看。汇率只覆盖已提供期间，缺失期间会提示，不能据此认为已支持所有未来月份。马来西亚仍未接入。

各浏览器的后续参数修改、合同删除及保存版本保存在 localStorage，互不共享，也不随 Git 同步。初始化仅补充缺少且未删除的合同，不覆盖已有参数，不恢复已删除合同。浏览器版本号从初始化版本开始，不复制原浏览器的操作历史。

以下资料初始化脚本用于以后更新基础数据，**首次运行无需执行**。脚本生成的 `analysis/` 为可选本地覆盖，同名附注文件优先使用本地版本，合同按编号合并并优先使用本地参数。需要分发新的统一基础数据时应更新 `prototype/seed-data/`，本地覆盖不会自动进入 Git。

汇率与日本合同更新：提供 `FX rate list.xlsx`、历史使用权资产附注和日本租赁文件后，运行 `python prototype/prepare_international.py`。脚本只读源文件，逐期核对日本分录，并生成本地覆盖文件。已有浏览器中的合同参数不会被覆盖。

折算使用年初期初汇率、截至报告月的年初累计平均汇率及期末汇率，单列折算差额；汇率缺失时保留原币并提示。保存附注版本时同时固定可用的折算结果与汇率依据。

美国合同初始化：提供 `US Lease Calculation 2021.0914.new office.xlsx` 及四份历史附注后，运行 `python prototype/prepare_us.py`。按已确认的期末付款口径计算，参数中保留条款登记为期初付的差异说明。免租期纳入确认及折旧；现值汇总后四舍五入、利息及折旧保留两位小数，末期结清尾差。

韩国合同初始化：提供 `韩国公司租赁-Korea Lease Calculation25.10-27.09.xlsx` 及 `25.使用权资产260630-OK.xlsx` 后，运行 `python prototype/prepare_korea.py`。按已确认的2025年10月至2027年9月共24个自然月、期末付款口径计算，保留原表头结束日差异说明；韩元金额四舍五入至整数，末期补提3韩元折旧尾差。不补录已经结束的旧合同。运行 `node prototype/check-korea.cjs` 核对6月原币附注、汇率折算及到期处置。

欧洲合同初始化：提供 `欧洲公司租赁/EU Lease Calculation.xlsx` 及四份历史附注后，运行 `python prototype/prepare_europe.py`。办公室及仓库均按已确认的不涨租、期末付款口径核算，合同条款差异保留在参数说明中；末期分别调平0.09欧元和0.08欧元折旧尾差。办公室出租方等未提供的档案信息标记待补充。

欧洲旧租赁作为固定历史来源保存在 `analysis/disclosures/fixed-history.json`，与可修改合同分开，金额追溯可查看来源。2026年初原值及累计折旧各214,482.46欧元，按6月附注列示当年处置；这是报告期归属，不认定实际处置日期。2025年3月、9月取已提供历史金额，9月后已提足折旧的余额承接至年末；其他未提供的2025年期间提示缺少历史记录。运行 `node prototype/check-europe.cjs` 核对四期原币附注、历史数据隔离、人民币折算及两份合同的到期处置。

当前附注按合同结束日自动处置：到期当期完成折旧后转销原值及累计折旧，本年后续期间仍列示本年累计处置，次年不重复列示。回看到期前期间不受影响，已保存的历史版本保持原样。

集团附注：完成各公司初始化后，提供2026年6月、9月使用权资产附注及 `00 合并报表-普源精电科技股份有限公司 2026 09.xlsx`，运行 `python prototype/prepare_group.py`。进入使用权资产附注，选择“集团合并”，点击普源集团缩略图进入明细。集团以人民币汇总当前公司单体，暂不纳入马来西亚，耐数电子与耐数信息全额抵消；公司列与抵消明细列默认折叠。原值采用借增贷减、累计折旧采用贷增借减，抵消明细随公司金额变化；金额可追溯至公司单体及合同。

`analysis/disclosures/opening-carry.json` 固化欧洲、日本、韩国2026年人民币期初承接差额，作为独立来源列示，避免重新折算覆盖上年末已报金额。该差额只影响期初与相应折算差额，不覆盖合同参数变更的计算结果；原币及已保存版本不受影响。`group-reference.json` 保存集团剔除马来后的核对基准，未提供期间不显示“核对通过”，缺少汇率时不生成不完整合并数。运行 `node prototype/check-group-disclosures.cjs` 验证6月、9月逐项核对、试算表净值、抵消方向及范围。

租赁负债附注：侧栏“租赁负债附注”提供公司缩略图、单体与集团视图。全部金额取自合同计算表；按报告日后十二个月（含第十二个月）本金减少额逐合同重分类，限于该合同账面负债余额。十二个月内结清的余额全额转流动部分；原币默认展示，外币可按现有汇率规则折算人民币。集团暂不含马来西亚，耐数电子、耐数信息全额抵消；公司列、抵消明细默认折叠。保存单体版本时冻结参数、计算表、重分类明细及当时可用的折算结果。

页面不列示旧报表核对状态与差异。开发核对可运行 `python prototype/prepare_liability.py` 提取本地 6 月、9 月资料，再运行 `node prototype/check-liabilities.cjs`；核对资料只供检查，不参与附注取数。历史附注与现有合同计算表不一致时保留计算表结果。

两个附注共用标题下方的“公司单体 / 集团合并”切换栏；单体与合并均以缩略图进入明细。切换口径保留报告期间与各附注最后查看的公司，侧栏切换附注类型时沿用当前口径。合并列表路由为 `#disclosures/group`、`#liabilities/group`，明细路由在后方追加 `/detail`。

## 项目结构

- `prototype/server.py`：本地服务及计算接口。
- `prototype/lease_engine.py`：付款安排、现值、利息及折旧计算。
- `prototype/contract-workspace.js`：合同台账及参数、计算表页面关联。
- `prototype/rent-phases.js`：租金阶段和付款规则。
- `prototype/contract-advanced.js`：高级财务参数。
- `prototype/index.html`、`prototype/style.css`、`prototype/calculation.css`：页面及样式。

`lease_linking.py` 中保留历史辅助代码，当前服务不开放相关接口。

## 检查

安装 Node.js 后，可运行前端业务检查：

```powershell
node prototype/check-contract-links.cjs
node prototype/check-financial-rules.cjs
node prototype/check-default-contract.cjs
```

完成上述本地资料初始化并启动服务后，可运行 `node prototype/check-international.cjs` 检查日本原币附注、汇率折算、缺失汇率、币种隔离和追溯合计。
美国数据初始化后运行 `node prototype/check-us-disposal.cjs`，核对四个历史期间及到期前、到期月、次年、多合同和外币折算处置逻辑。

完整计算回归检查：

```powershell
python -m unittest discover -s prototype -p test_lease_engine.py
```

其中部分历史回归用例需要在项目根目录提供本地样本 `西安公司使用权资产.xlsx`。合同原件、样本、截图、分析输出及日志均不提交到仓库；日常运行服务不需要这些文件。

当前版本用于本地验证。多人使用、服务器部署、权限与数据持久化需进一步实现。

### 耐数集团附注

两个附注的集团合并列表均提供普源集团和耐数集团缩略图。耐数集团仅包含北京普源耐数电子有限公司及其全资子公司北京耐数信息有限公司；出租方不在此合并范围内，两家公司租赁不抵消。普源集团仍全额抵消两家的内部租赁。金额追溯按所选集团展示，新增同一成员公司的合同自动纳入。

运行 `node prototype/check-naishu-group.cjs` 验证两种附注的合并范围、无抵消汇总、重分类、额外合同纳入、出租方排除和数据不变性。

初始化数据验证：运行 `python -m unittest discover -s prototype -p test_seed_data.py` 检查无本地资料时的数据加载和本地覆盖；运行 `node prototype/check-bundled-data.cjs <服务地址>` 检查 9 份合同、8 家公司及 6 月/9 月两套集团附注。
